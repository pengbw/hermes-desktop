# 工作室流程使用说明

## 概述

工作室（Studio）是一个基于 AI 角色的项目协作系统。每个项目由多个 AI 角色（如产品经理、高级开发者、测试分析师等）组成，按照预设的工作流（Workflow）自动推进任务。每个角色产出的文档/代码/报告称为「产物」（Artifact），角色之间通过产物传递完成协作。

---

## 核心概念

### 角色（Role）

每个角色对应一个内置的 AI 智能体，拥有独立的：

- **名称 & 昵称**：显示用的标识
- **职责**：定义该角色在项目中承担的任务
- **灵魂设定**：影响 AI 回答风格和行为方式的角色扮演设定
- **图标**：视觉标识

项目中可以自定义角色的职责和灵魂设定。

### 产物（Artifact）

产物是角色完成工作后产出的文档或代码，具有以下属性：

- **类型**：如「需求文档」、「代码实现」、「测试报告」等
- **标题**：产物名称
- **内容**：产物的实际内容（Markdown 格式）
- **状态**：见下文状态流转

### 工作流（Workflow）

工作流定义了角色之间的产物传递关系。每条工作流记录包含：

| 字段                | 说明                         | 示例                           |
| ------------------- | ---------------------------- | ------------------------------ |
| `from_role_id`      | 上游角色（为空表示项目启动） | `product_product-manager`      |
| `to_role_id`        | 下游角色                     | `engineering_senior-developer` |
| `artifact_type`     | 传递的产物类型               | `需求规格`                     |
| `transition_type`   | 流转类型                     | `auto_push` / `need_confirm`   |
| `reject_to_role_id` | 驳回时回退到的角色           | `engineering_senior-developer` |

---

## 流转类型

### `auto_push` — 自动推送

角色完成工作后，产物自动传递给下游角色，无需人工审批。

```
角色 A 产出 → 自动触发角色 B 开始工作
```

### `need_confirm` — 需审批

角色完成工作后，产物进入「待审批」状态，需要人工点击「通过」或「驳回」。

```
角色 A 产出 → 进入待审批 → 人工审批 → 通过 / 驳回
```

- **通过**：产物流转到下游角色，继续流程
- **驳回**：根据 `reject_to_role_id` 回到指定的上游角色，该角色收到驳回原因后重新工作

## 产物状态流转

```
            角色开始工作
                 │
                 ▼
           in_progress（进行中）
                 │
         角色提交产出
                 │
        ┌────────┴────────┐
        ▼                  ▼
   auto_push          need_confirm
        │                  │
        │                  ▼
        │          pending_approval（待审批）
        │                  │
        │        ┌─────────┴─────────┐
        │        ▼                   ▼
        │    approved（通过）     rejected（驳回）
        │        │                   │
        │        ▼                   ▼
        │   触发下游角色         回退到上游角色
        │                       重新 in_progress
        │
        ▼
   触发下游角色
```

## 操作指南

### 1. 创建项目

1. 在工作室页面点击「新建项目」
2. 选择一个行业模板
3. 填写项目名称、描述
4. 可选自定义每个角色的职责和灵魂设定
5. 点击创建

系统会自动：

- 初始化项目角色
- 创建工作流定义
- 创建第一个任务
- 启动流程，将第一个角色设为运行状态

### 2. 与角色对话

1. 在项目面板中点击某个角色
2. 在聊天窗口与该角色对话
3. 角色会根据其职责和灵魂设定回答你的问题
4. 角色产生最终输出后会自动提交产物

### 3. 审批产物

当角色提交一个 `need_confirm` 类型的产物时：

1. 产物状态变为 `submitted`（已提交）
2. 前端弹出审批窗口，显示产物内容
3. 你可以：
   - **通过**：点击通过并填写审批意见，产物流转到下游角色
   - **驳回**：填写驳回原因，产物回到指定上游角色重做

### 4. 驳回后的流程

1. 当前产物标记为 `rejected`
2. 系统查找 `reject_to_role_id` 指定的上游角色
3. 为该上游角色创建一个「修改稿」产物（状态 `in_progress`）
4. 自动通知上游角色，携带驳回原因
5. 上游角色需根据驳回意见修改后重新提交

### 5. 查看项目进度

在工作流步骤视图中可以看到：

- 每个步骤的执行状态（运行中 / 完成 / 驳回 / 待审批）
- 每个角色的产物列表
- 流程的当前进度

| `projects`           | 项目基本信息   |

| ---------------------------- | -------------- |
| `chat_with_project_role`     | 与项目角色对话 |

| `reject_project_artifact`    | 驳回产物       |

## 常见问题

### Q: 为什么驳回后没有回到正确的角色？

确保 `project_workflows` 中 `need_confirm` 类型的步骤正确配置了 `reject_to_role_id`。系统会先按 `artifact_type` 精确匹配，匹配不到时回退为按角色匹配。

### Q: 可以自定义模板吗？

目前模板数据在 `src-tauri/resources/project-templates.json` 中定义，修改后重新构建即可。未来版本将支持前端可视化编辑模板。

### Q: 角色的产出物保存在哪里？

产出物以 Markdown 文件保存在项目工作空间目录下，路径在 `app_config` 的 `workspace_root` 配置中指定。
