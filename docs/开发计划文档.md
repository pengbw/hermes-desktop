> 版本：v1.0

---

## 编码规范（贯穿所有阶段）

1. **代码逻辑严谨**：所有分支必须覆盖完整，错误处理不可省略，数据库操作需使用事务保证一致性
2. **代码排版整洁**：统一使用项目已有格式（Rust 用 `cargo fmt`，TypeScript 用 Prettier），缩进、空行、命名风格与现有代码保持一致
3. **废弃代码及时清理**：删除不再使用的函数、变量、import、注释掉的代码块，不留死代码
4. **关键代码加注释**：
   - 数据库迁移：注释版本号和用途
   - 核心业务逻辑（工作流触发、任务分配、产物审批）：注释关键步骤的意图
   - 复杂 SQL 查询：注释查询目的
   - 前端状态管理：注释状态计算逻辑
5. **前后端接口对齐**：每次新增/修改 Tauri Command，同步更新 `types.ts` 中的类型定义

### 1.5 R8：后端推送数据自动刷新（含防抖）

**涉及文件**：

| 文件                                      | 操作 | 说明                                        |
| ----------------------------------------- | ---- | ------------------------------------------- |
| `src-tauri/src/commands/project.rs`       | 修改 | 新增 DebouncedEmitter，关键操作后 emit 事件 |
| `src-tauri/src/commands/mod.rs`           | 修改 | 注册新模块                                  |
| `src/components/studio/ProjectDetail.tsx` | 修改 | 注册/注销事件监听，按需刷新                 |
| `src/services/tauri/TauriEvents.ts`       | 修改 | 新增项目数据变更事件监听                    |

**后端开发步骤**：

1. 新增 `DebouncedEmitter` 模块（可放在 `commands/helpers.rs` 或新建 `commands/events.rs`）：

   ```rust
   use std::collections::HashMap;
   use std::sync::Mutex;
   use tauri::AppHandle;

   pub struct DebouncedEmitter {
       pending: Mutex<HashMap<String, Vec<String>>>,
       debounce_ms: u64,
   }
   ```

   - `add_change(project_id, data_type)`：加入待推送队列
   - `flush(project_id)`：立即推送并清空队列
   - 使用 `tokio::time::sleep` 实现 500ms 防抖

2. 在以下操作后调用 `add_change` + emit 即时事件：
   - `auto_delegate_chat` 完成 → 即时 `task_status_changed` + 防抖 `["tasks", "artifacts", "members"]`
   - `approve_project_artifact` → 即时 `artifact_status_changed` + 防抖 `["artifacts", "workflow_steps", "members"]`
   - `reject_project_artifact` → 即时 `artifact_status_changed` + 防抖 `["artifacts"]`
   - `trigger_workflow_execution` → 即时 `workflow_step_changed` + 防抖 `["workflow_steps", "artifacts"]`
   - `assign_task` → 即时 `task_status_changed` + 防抖 `["tasks", "members"]`

3. 即时事件 payload 格式：

   ```json
   { "projectId": "xxx", "artifactId": "xxx", "oldStatus": "in_progress", "newStatus": "submitted" }
   ```

4. 防抖事件 payload 格式：
   ```json
   { "projectId": "xxx", "changes": ["tasks", "artifacts", "members"] }
   ```

**前端开发步骤**：

1. `TauriEvents.ts`：新增事件监听函数

   ```typescript
   export function onProjectDataChanged(
     callback: (payload: ProjectDataChangePayload) => void
   ): () => void;
   export function onArtifactStatusChanged(
     callback: (payload: ArtifactStatusChangePayload) => void
   ): () => void;
   export function onTaskStatusChanged(
     callback: (payload: TaskStatusChangePayload) => void
   ): () => void;
   ```

2. `ProjectDetail.tsx`：
   - `useEffect` 中注册事件监听器
   - 收到 `project_data_changed` → 根据 `changes` 数组调用对应的 refresh 函数
   - 收到 `artifact_status_changed` → 触发审核提醒（R7）
   - 组件卸载时注销所有监听器

3. 定义类型：
   ```typescript
   interface ProjectDataChangePayload {
     projectId: string;
     changes: Array<"tasks" | "artifacts" | "members" | "workflow_steps">;
   }
   ```

**测试验证**：

- 角色完成工作 → 前端自动刷新任务和产物列表
- 审批通过 → 前端自动刷新产物和工作流步骤
- 短时间内多次变更 → 只触发一次刷新（防抖验证）

**前端开发步骤**：

1. 扩展 `VirtualOffice` 的 `members` 属性：

   ```typescript
   interface OfficeMember {
     roleId: string;
     name: string;
     icon: string;
     isWorking: boolean;
     status: "working" | "idle" | "waiting_approval"; // 新增
   }
   ```

2. `ProjectDetail.tsx`：
   - 修改状态计算逻辑：
     ```typescript
     const getMemberStatus = (memberRoleId: string): "working" | "idle" | "waiting_approval" => {
       const artifact = projectArtifacts.find((a) => a.roleId === memberRoleId);
       if (artifact?.status === "in_progress" || artifact?.status === "pending") return "working";
       if (artifact?.status === "submitted") return "waiting_approval";
       return "idle";
     };
     ```

3. `OfficeScene3D.ts`：
   - 新增 CSS2DRenderer 标签渲染
   - 标签内容根据 status 显示：
     - `working` → 🟡 忙碌
     - `idle` → 🟢 空闲
     - `waiting_approval` → 🟠 待审批
   - 标签位置：角色头顶偏上
   - 标签样式：半透明背景、圆角、小字体
   - `updateMembers` 方法：根据 status 更新行为和标签

4. 依赖 R8 的推送机制：
   - 收到 `member_status_changed` → 更新成员状态 → 传入 VirtualOffice

**测试验证**：

- 角色开始工作 → 回到工位，头顶显示"🟡 忙碌"
- 角色完成工作提交审核 → 离开工位，头顶显示"🟠 待审批"
- 角色审批通过 → 离开工位，头顶显示"🟢 空闲"
- 空闲角色随机执行空闲动作
